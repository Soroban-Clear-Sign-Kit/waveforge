# Implement check R11 for Soroban contract instance TTL extension

## Context
In src/repo/r8.ts and src/repo/index.ts, on-chain verification confirms contract existence, but does not evaluate state expiration risks. On Stellar Soroban, contract instance and storage entries expire unless periodic TTL (Time To Live) extension routines are executed. Projects with long-lived smart contracts must manage contract storage lifetimes to prevent contract archival. Implementing check R11 will analyze contract source code in contracts/ and test setups to determine whether TTL extension calls (such as `extend_ttl`) are present in contract logic.

## Requirements
- Introduce check module `src/repo/r11.ts` to inspect Rust contracts for contract storage TTL extension logic.
- Specify authorization requirements: all state modifications and TTL extension calls must define who must authorize state changes using require_auth.
- Require comprehensive unit tests for contracts verified through cargo test.
- Verify contract compilation and packaging with stellar contract build and inspect Wasm size.
- Detect `extend_ttl` or `extend_ttl_instance` invocations across contract source files in contracts/.
- Emit PASS when contract storage lifetime management is detected, and WARN with TTL documentation when absent.
- Register check R11 into the repository readiness pipeline in src/repo/index.ts.
