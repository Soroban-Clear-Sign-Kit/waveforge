# Support Go language repositories in repository CI verification

## Context
In src/repo/r6.ts and src/repo/index.ts, our repository readiness check currently focuses on Node and Rust/Cargo workflows when verifying pull request CI jobs. Several Stellar ecosystem backend projects, indexers, and horizon plugins are built using Go (such as go-stellar-base). Expanding our CI check architecture to recognize Go projects (via go.mod) and verify that CI workflows execute `go test` and `golangci-lint` will ensure that Go maintainers can utilize waveforge for Stellar Wave readiness.

## Requirements
- Update project type detection in src/repo/index.ts to identify Go repositories by checking for go.mod.
- Extend rule R6 in src/repo/r6.ts to check for `go test ./...` and linting steps in .github/workflows/*.yml.
- Ensure integration between language detection and CI verification supports hybrid repositories.
- Add test fixtures under test/fixtures/repos/ for valid and failing Go repository CI workflows.
- Update test/repo-checks.test.ts to validate Go CI workflow checks.

## Done when
- [ ] Language detection identifies Go projects by the presence of go.mod.
- [ ] Rule R6 asserts that pull request CI workflows execute `go test` when go.mod is present.
- [ ] Rule R6 warns if linting tools such as `golangci-lint` or `staticcheck` are omitted from Go CI.
- [ ] Fixture repositories under test/fixtures/repos/ include Go test workflows.
- [ ] Full integration test suite in test/repo-checks.test.ts confirms Go CI verification passes.
